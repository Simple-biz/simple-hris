# Project Context for LLMs

Simple HRIS is a **payroll processing tool** for a Philippines-based outsourcing company. Its primary workflow takes a weekly Hubstaff hours CSV export, computes base pay with overtime, applies per-department bonus rules, validates against a master employee list, and produces a final payout ledger.

Read the documents in this folder **before** making changes to the codebase. They capture business rules and architectural decisions that are not obvious from the code alone.

## Quick Facts

- **Currency**: Philippine Peso (₱), `en-PH` locale
- **Overtime threshold**: 40 hours/week
- **Hours arithmetic**: Integer seconds (avoids float errors)
- **Employee identity key**: Email address (normalized: trimmed + lowercased)
- **Employee IDs (YYMM-NNNN)**: Derived display-only, never persisted
- **Dual-table writes**: Add/delete employee always touches both `employee_hourly_rates` and `global_master_list`
- **Column names have spaces**: PostgREST quoted identifiers (`"Work Email"`, `"Total worked"`, etc.)
- **Date columns can mismatch**: DB may have ISO (`"2026-03-24"`) while CSV has `"Mon 3/24"`. The upload code does date-aware mapping; the client also re-parses the CSV as a fallback.
- **PAB month boundaries**: A week belongs to the month containing its Monday. Start = first Mon on/after 1st; End = Fri of last week whose Mon is in the month (may spill into next month).
- **PAB canonical column resolution**: Supabase stores `monday`/`tuesday` columns; the merge logic resolves them to ISO dates using source filenames (`resolveCanonicalColumnsToIso()`).
- **Employee Dashboard "All Time"**: Aggregates pay across all source files with per-file regular/OT split (each file split at 40h, then summed). PAB shows eligible months × ₱5,000.
- **PA detection requires daily data**: If daily columns are null in Supabase (column-name mismatch from old upload), a warning banner in Step 3 tells the user to re-upload.
- **Step 5 (HSL Payroll)**: Dedicated HSL step — Initial Pay + KPI Bonus (from HSL Bonus Calculator) + PAB (₱5,000 if eligible, Mon–Sun week logic) + Tech Bonus (₱1,850 if eligible); both PAB and Tech Bonus are included in Total Pay per row and footer total
- **Step 6 (Dispatch)**: Currently a placeholder — no payment API is called
- **Hogan Cycle toggle**: Flag used by HSL PAB period logic (`hslAdjustedPabEnd`); full date-range filtering still pending
- **Lead Gen department**: No bonuses, explicitly excluded by policy
- **Auth + RBAC** *(implemented; overhauled 2026-06-18)*: NextAuth Google SSO restricted to the `simple.biz` Workspace; JWT stamped with roles from `employee_roles`. The edge gate (`proxy.ts` under Next 16, formerly `middleware.ts`) gates every page route + enforces `?email=` ownership, and returns a JSON 401 (not an HTML redirect) for `/api/*`. Two authz layers: **dashboard-only role grants** (a role just unlocks a whole dashboard) + a Hidden/View/Edit per-tab overlay (`employee_feature_permissions`) that now spans **every** role dashboard **and is enforced on all write APIs** (view-only users are blocked from POST/PATCH/DELETE via `requireFeatureEdit`); `admin` bypasses. Assigning a role auto-provisions sensible tab permissions. Role/permission changes trigger a force-logout map (+ live "reset session" via `SessionInvalidationWatcher`) that invalidates stale JWTs. See [rbac-feature-permissions.md](../features/rbac-feature-permissions.md).
- **Eight role dashboards**: Accounting (`/`), Admin (`/admin`), Employee (`/employee`), Manager (`/manager`), HR (`/hr`), CEO (`/ceo`), Orphanage (`/orphanage`), Contractor (`/contractor`); Payroll Clerk dispatch is at `/payroll-clerk` and also the Accounting Payment Dispatch tab. Users land on their highest-priority view and hop between entitled views via the sidebar ViewSwitcher (`src/lib/rbac/views.ts`).
- **Employee Portal**: Accessible at `/employee?email=...` — provides Dashboard (hours/pay/PAB), Profile (with bank info), and Settings (bank info editing).
- **System Overview CSV selector**: Dropdown to view stats for a specific source file or "All Time" (aggregated). Defaults to latest file.
- **Bonus & Status panel**: Real-time PAB eligibility metrics (eligible/not eligible counts + progress bar), Technology Bonus status; dispute counts still summarized at a high level (detailed flow is `pab_day_disputes` / [BUSINESS_LOGIC.md](./business-logic.md#pab-day-dispute-system)).
- **Rates avatars**: Employee table and profile modal show avatars (photo/Gravatar/initials). Photo URL fields are hidden from the field list.

- **PostgREST 1000-row cap** *(discovered 2026-07-09; systemic sweep 2026-07-30)*: PostgREST silently caps un-paginated reads at **1000 rows** — a single `.range(0, 9999)` returns ≤1000 with **no error**. **Always read whole tables/views through `selectAllPaged`** (`src/lib/supabase/select-all-paged.ts`): build the query *inside* the closure (PostgREST builders are single-use), apply the handed `.range()`, and add a stable `.order()`. **A per-cycle / per-week / per-department filter is NOT a bound** — one live pay cycle stages 1,020+ rows. The roster hit **1,296** on Jul 30 and a 22-agent audit found **16 un-paged readers silently dropping their tail with live damage**: Payment Dispatch routing missing 20 people, outstanding-pay totals missing ~470 recipients, ~296 people never notified "Salary Ready to View", 126/448 HSL people on the wrong week model, ~296 missing from manager Team pages, and a work-email suggester that could re-mint a taken address (all fixed, `2829a6d`). Two 2026-07-09 candidates are **still open**: `fetchMasterMin` (`current-pay.ts`) and the rates CSV sync existing-row lookup. See [data-sources.md](./data-sources.md#data-integrity-gotcha-postgrest-1000-row-default-cap-discovered-2026-07-09-systemic-sweep-2026-07-30).

- **Mid-week rate changes prorate, and the paystub explains it** *(2026-07-30, no migration)*: a dated rate change (usually a department transfer) inside the pay week pays the line at two rates. The engine is `src/lib/payroll/prorate-mid-period.ts`, mirrored in **both** engines (wizard Step-2 calc **and** `current-pay.ts`'s `computeProratedRowPay` + the disbursement-reports seeding path) so they can never disagree. The statement keeps the **same row** and adds an amber **Prorated** chip, a **`₱old → ₱new`** cell, and a per-rate hour basis. Two layered rules: **catalog-consistency** — a Payment Catalog-managed person prorates through dated history only when the history rate as of their last worked day **equals the structure** (PHP only), else it fails closed to the flat catalog week (`historyMatchesCatalogAsOf`); and **HSL transfer-week scoping** — the +₱15/h weekend premium starts on the transfer's **effective date**, so weekend days before it stay plain-rate (`resolveHslWeekScope`). Audit conflicts with `scripts/audit-catalog-history-conflicts.mjs` (17 people pending Accounting). See [paystub-dispatch.md](../features/paystub-dispatch.md).
- **HSL paystubs itemize Weekend Hours** *(2026-07-30; display merged 2026-08-07)*: the payload's `weekend` block is a **carve-out**, not an addition — `hours.*` and `pay_php.regular/ot` stay full-week totals and the weekday lines are derived by **subtraction**, so anything summing payloads is unchanged. Weekend hours can be **regular OR OT** (the 40h cap is chronological) and the block keeps that split, but the statement renders **ONE merged "Weekend Hours" row** (`weekendHours`/`weekendPay`/`weekendBasis` on `PayStubView`; per-rate basis because the buckets pay at `base+15` vs `otRate+15`) — "Overtime" is the only OT-labelled line. `weekend: null` / a pre-2026-07-30 payload renders the classic two lines.
- **"Total payout" = the full pay run** *(2026-07-30)*: the Accounting Overview hero adds `extrasTotalPhp` (KPI/catalog bonuses, Notes adjustments, orphanage pay, MESA, paid urgent of the dispatch week) from payroll's own staged/live figures via `GET /api/accounting/payout-extras`, on all three surfaces incl. the CEO-mirrored snapshot. **PAB stays hero-side** (adding staged PAB too would double-count). Open gap: the salary base is still sheet-only rates (~₱213K catalog drift; ~17 catalog-paid people with no rates row are invisible to it). See [accounting-total-payout.md](../features/accounting-total-payout.md).
- **One email ≠ one person** *(2026-07-30)*: `bonus_catalog_applied` rows are keyed personal-email-first, and a master-list email shared by two differently-named rows used to merge both people's KPI bonuses onto both paystubs. Resolution is now collision-aware by the row's `employee_name` snapshot (`manager-bonus-attribution.ts`) — stored keys, the KPI Calculator and QC are untouched; unattributable rows are paid to **nobody** and surfaced in an amber Additions banner. Verify with `scripts/verify-kpi-shared-email-split.mts`.
- **In-`<main>` surfaces stay under body-level chrome** *(2026-07-30)*: `<main>` carries `isolate` (so the collab avatar rail can't float over modal scrims), which traps any `fixed inset-0` child beneath the sidebar (`md:z-30`). A full-screen or floating surface rendered inside `<main>` **must portal to `document.body`** to beat the sidebar or a dialog — `CobrowseSurface` does this internally, covering all three of its mounts. See [accounting-cobrowse.md](../features/accounting-cobrowse.md).
- **A stale Google-Sheet paste silently reverts applied transfers** *(2026-07-30 incident, 13 people restored)*: the Sheet is the sync's truth for `(Work Email, Department)`, so pasting an older snapshot wipes every department change since — the sync then mints a duplicate in the old department or strands the new-department row as invisible, while the transfer record still reads `applied`. Detection needs a **full Sheet-vs-DB consistency sweep**, not a transfer-record audit (a Sheet-only move has no transfer record at all). Fix = flip the Sheet cell + restamp the DB row visible + delete the sync-minted duplicate. Playbook in [department-transfers.md § 6](../features/department-transfers.md).
