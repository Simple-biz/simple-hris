## 1. Payment Catalog is authoritative for hourly rates

The Payment Catalog (`payment_catalog_pay_structures`) is now the source of truth for hourly rates, applied at **compute time** via a new pure in-memory overlay — `src/lib/payroll/resolve-rate.ts`. Nothing here writes to the DB.

### Overlay shape

- `buildCatalogRateIndex(structures)` → `CatalogRateIndex { byEmail, byDeptKey }`: employee-scoped structures indexed by normalized email, department-scoped by canonical department key (`src/lib/payroll/resolve-rate.ts:66`).
- **Two-function split** (not a single resolver): `resolveEmployeeCatalogRate(index, emails, fxRate)` and `resolveDeptCatalogRate(index, deptRaw, fxRate)`. Each returns a `ResolvedCatalogRate { regPhp, otPhp, regNative, otNative, currency, source }`.
- **Final priority** — callers interleave the sheet themselves:

  ```
  effective = resolveEmployeeCatalogRate(...)   // INDIVIDUAL (negotiated rate, always wins)
           ?? sheetRate                          // SHEET / history (employee_rate_history / employee_hourly_rates)
           ?? resolveDeptCatalogRate(...)         // DEPARTMENT base (fallback for people with no individual rate)
  ```

  The department structure is a **base/fallback, NOT an override** (`resolve-rate.ts:1`–`31`).
- **Currency**: each structure carries PHP or USD. A USD rate is converted to its PHP-equivalent (× FX) in `toResolved()`; OT defaults to `defaultOtRate(reg)` (1.5×) when the structure omits it. Native rate + currency are returned for display.

### Wired consumers

| Surface | File | When applied |
|---|---|---|
| Live Payment Dispatch | `src/lib/payroll/current-pay.ts` | **Always** (live cycle) |
| Payroll Wizard (client calc + everything staged) | `src/components/PayrollWizard.tsx` | Only when `!isReplay` (past replays keep dated history) |
| Manager + employee monthly estimate | `src/lib/payroll/member-monthly-pay.ts` | Current/future months only |
| Self-view rates | `app/api/employee-hourly-rates/route.ts` (`?email=` branch) | Dashboard / Profile / MESA |
| My Hours calendar per-day estimate | `src/components/employee/EmployeeMyHours.tsx` | — |

### USD corruption fix

`app/api/payment-catalog/pay-structures/route.ts` — `syncRateHistory()` now **skips** the PHP-denominated rate history / cache / Sheet writes for USD structures (`if (s.currency !== 'USD')`, `pay-structures/route.ts:47`–`53`); the overlay handles USD→PHP at compute time. Writing a raw USD number into a PHP table had been corrupting pay. The employee notification still fires, and `currency` was added to the audit/notification payload.

### Known gap

The admin **Rates** tab still shows the cached sheet number for catalog-covered employees because it reads the cache table directly (`Rates.tsx` intentionally left as-is). This is display-only; pay math uses the overlay.

## 2. Google Sheet rates sync disabled (manual CSV upload still writes pay)

`app/api/cron/sync-rates-from-sheet/route.ts` now short-circuits behind the constant `RATES_SHEET_SYNC_DISABLED = true` (`route.ts:41`): after the auth check it returns `{ success:false, disabled:true, ... }` with HTTP **200** *before* touching any pay table. Rate changes flow exclusively through the Payment Catalog; the `employee_hourly_rates` / `employee_rate_history` sheet layer is now a frozen middle-layer snapshot.

The **separate manual CSV rates upload** (`employee-hourly-rates-upload`) was deliberately left **ENABLED** and still writes pay — only the Google Sheet sync was frozen.

`src/components/admin/AdminCsvImports.tsx` handles the new `disabled` response case with `toast.info` ("Rates sync disabled — managed in the Payment Catalog") instead of an error toast.

## 3. Onboarding — Intellectual Property Assignment (first step) + preview mode

A new standalone **"Intellectual Property Assignment, Talent Release, and Copyright Waiver"** is now the **first step** of the public onboarding flow (before all other paperwork), mirroring the W-8BEN pattern: on-screen document text + acknowledgement checkbox + Name / drawn-signature / Date block.

- **Date auto-stamps client-side** in `Month D, YYYY` format using the hire's **local** day (not server UTC), read-only.
- On submit the server renders a filled PDF via **pdf-lib** (`src/lib/onboarding/ip-assignment-pdf.ts`) — name, drawn signature, checked acknowledgement box, date — and stores it in the `hr-onboarding-files` Supabase Storage bucket at `<submission_id>/ip-assignment.pdf`.
- The acknowledgement mark is drawn as **two vector strokes (a real checkmark)** because the checkmark glyph isn't in Helvetica/WinAnsi encoding (uses `LineCapStyle`).
- **HR surfaces**: a new **IP Assignment** tab + a Summary block in the submission-detail modal, with a View/Download link via signed URL (`app/api/hr/onboarding-submissions/[id]/route.ts`, `src/lib/supabase/hr-onboarding-submissions.ts`).

> **PENDING migration #73** — `references/migrations/add_ip_assignment_to_onboarding.sql` adds **6 columns** to `hr_onboarding_submissions`: `ip_agreement_agreed`, `ip_agreement_name`, `ip_agreement_signature`, `ip_agreement_date`, `ip_assignment_file_path`, `ip_assignment_file_name`. Required before the feature works in production.

### No-save preview mode

- Keyed on the literal token `'preview'` (`/onboarding/preview`). `const isPreview = token === 'preview'` (`app/onboarding/[token]/page.tsx:163`). `isPreview` short-circuits the load effect (no API call, `page.tsx:182`), skips per-step validation (`page.tsx:342`), guards the live W-8BEN upload, and shows an amber **"Preview mode — nothing is saved or submitted"** banner. Real invite tokens are 32-byte random strings, so `preview` never collides; both preview and live render the same `OnboardingFormPage`.
- **Preview Submit is a dry-run**: new public `POST /api/onboarding/ip-assignment-preview` renders the real signed PDF from `{ name, signatureDataUrl, dateIso }` and returns `application/pdf` with **no DB/storage writes** (under the rate-limited `/api/onboarding/` prefix). In preview the footer Submit is relabeled **"Generate signed PDF"** (`page.tsx:620`) and a dashed "Preview test" panel offers a generate button on the IP step.
- The HR **"Onboarding Paper Work Template"** link card (beside the "Licenses available" meter in `HrOnboardingForm`) points to the in-app `/onboarding/preview` route, NOT a Google Doc.

### Dark-mode + animation polish

- An unlayered `!important` CSS rule scoped to `.onboarding-public` forces input/textarea/select text to zinc-900 and `color-scheme:light`; `.dark`-scoped rules force agreement body to zinc-700 / headings to zinc-900 (excluding emerald/amber/yellow accent classes). The HR review modal reuses the same agreement components but is intentionally **not** `.onboarding-public` so it keeps proper dark-mode rendering.
- Step transitions use a directional slide+fade via `motion/react` (`AnimatePresence mode='wait'`, ~260ms), honoring OS reduce-motion (cross-fade fallback); applies to both `/onboarding/preview` and live `/onboarding/<token>`.

See [features/onboarding-ip-assignment.md](../features/onboarding-ip-assignment.md).

## 4. Per-employee paystub dispatch (depth)

Builds on the per-employee dispatch model documented in [features/paystub-dispatch.md](../features/paystub-dispatch.md).

> **PENDING migration #72** — `references/seed_paystub_dispatch_queue.sql` creates `paystub_dispatch_queue`: one **UNIQUE (cycle_source_file, recipient_email)** row holding the authoritative paystub `payload` (JSONB) + `pay_period`, `amount_php`/`amount_usd`, `excluded` + `exclude_reason`, plus `sent_at`/`sent_by`/`send_count`/`last_error`/`locked_at`/`locked_by`. Includes email-normalize + `updated_at` triggers, and re-asserts `app_settings` in the `supabase_realtime` publication. The wizard's "Lock & Send" 500s until this is run.

- **Wizard step-8 button** is now **"Lock in Values & Send to Payment Dispatch"** (`PayrollWizard.tsx:10790`): it **stages** each payable employee's payload to `paystub_dispatch_queue` via `POST /api/paystub-dispatch-queue` (`requireElevatedSession`) instead of batch-emailing, still publishes the `final_pay` snapshot, sets the report, and advances to step 9.
- **Emails fire one-by-one on Lenny's Mark Paid**: `POST /api/payment-dispatches` at `status='paid'` looks up the staged row and fires the n8n paystub webhook for just that person via `forwardPaystubDispatch` (`src/lib/payroll/paystub-dispatch.ts` — 25s `AbortSignal.timeout`, `resolveWebhookUrl('paystub_dispatch')` with `N8N_DISPATCH_WEBHOOK_URL` fallback). Best-effort: never fails the payment, returns `{ paystub: { staged, sent, error } }`. Scope-safe — MESA + orphanage dispatch routes do **not** fire a salary paystub.
- **Validation step EXCLUDE tickbox** (everyone defaults to Pay); the excluded set persists per pay-period at `app_settings` key `payroll.wizard.exclusions.<sourceFile>`; totals/counts reflect payable rows only; excluded rows dim.
- **Excluded tab = cross-cycle arrears ledger**: `GET /api/paystub-dispatch-queue/arrears` returns per-employee `{ totalPhp, totalUsd, cycles[] }` of unsettled excluded cycles (settled = a `status='paid'` `payment_dispatches` row). UI shows "Owed ₱X" totals, per-cycle breakdown, a per-row **Pay now**, and a **Settle ₱X** action that loops unpaid cycles (failure-tolerant — collects per-cycle outcomes, never throws mid-loop, so retries only re-run still-unpaid cycles). Plus a bank chip + single-select bank filter.
- **Realtime reversible wizard dispatch lock**: per-cycle flag `app_settings` key `payroll.dispatch_lock.<sourceFile>` = `{locked, lockedAt, lockedBy}`; new hook `useWizardDispatchLock`. "Lock & Send" sets `locked=true`; the Dispatch step shows a "Locked — Payment Dispatch is live" banner + Unlock (payroll/admin only). `useDispatchQueue` derives `wizardReady` (absent = unlocked; fail-open only on fetch error) and empties rows when unlocked. Reports/Urgent/Orphanage tabs are **not** gated.
- **Master-List queue filter**: `computeCurrentPay()` returns `masterEmails` (all work/personal/alternate emails in `active_employees`); `useDispatchQueue` filters pending + excluded rows to those (fail-open if missing), removing stale/off-boarded rows.
- The legacy batch route `POST /api/dispatch-paystubs` now has **zero callers** (doc-comment only) and was given an auth gate.
